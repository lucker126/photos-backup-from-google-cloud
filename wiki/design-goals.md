# Цели и принципы проектирования

## Основные цели

1. **Безопасность данных** — файлы не должны теряться ни при каких условиях
2. **Автоматизация** — минимум ручных действий после настройки
3. **Восстанавливаемость** — прерывание не ломает состояние, перезапуск продолжает с места остановки
4. **Прозрачность** — все действия логируются, состояние можно проанализировать offline
5. **Локальность** — никакие данные не передаются третьим сторонам, кроме Google

## Принципы

### 1. Manifest как единственный источник истины

Файл `backup_manifest.json` — единственное место, которое "знает", какие файлы уже сохранены. Это позволяет:
- Перезапускать скрипт без риска дублирования
- Проверять состояние без запуска браузера
- Восстанавливаться после сбоев

### 2. Удаление только после подтверждения

Любой файл удаляется из облака только когда:
- Он скачан и распакован
- Его SHA-256 хеш подтвержден на диске
- Он записан в manifest с `files_verified=true`

### 3. Явность магии

В браузерной автоматизации много неявного (таймауты, фокус, виртуальный DOM). Мы:
- Явно ждем элементы (`wait_for_selector`, `wait_for_timeout`)
- Явно проверяем состояние (`aria-checked`)
- Явно обрабатываем прокрутку (шаг, пауза)

### 4. Dry-run по умолчанию

Первый запуск всегда безопасен. Конфиг `DRY_RUN_DELETE=true` означает: скрипт имитирует удаление в логах, но не нажимает кнопку корзины.

### 5. Ограничения на удаление

Даже в боевом режиме есть ограничения:
- `MAX_DELETE_BLOCKS_PER_RUN` — лимит блоков на удаление за один запуск
- `DAYS_TO_KEEP_IN_CLOUD` — не удаляем молодые файлы

## Что НЕ является целью

- ❌ Скорость — эмуляция кликов не может быть быстрой
- ❌ Кроссплатформенность — Windows-специфичные пути, `start_bot.bat`
- ❌ Headless-режим без глюков — Google детектирует headless, рекомендуется `HEADLESS_MODE=false`

## Компромиссы

| Мы выбираем | Вместо | Потому что |
|-------------|--------|-----------|
| Playwright | Selenium | Быстрее, стабильнее, встроенный браузер |
| Точный клик по aria-label | CSS-классы | Google перегенерирует классы на каждом билде |
| SHA-256 | Размер файла | Размеры могут совпадать случайно, хеш — нет |
| Try-except с ретраями | Одна попытка | UI Google медленный и непредсказуемый |
