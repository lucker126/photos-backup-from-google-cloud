# Безопасность данных

Многоуровневая защита от потери фотографий. Ни один файл не удаляется из облака без подтвержденной локальной копии.

## Уровень 1: DRY-RUN по умолчанию

```json
{ "DRY_RUN_DELETE": true }
```
- Любое "удаление" только логируется: `[DRY-RUN] Удалил бы блок...`
- Кнопка корзины **не нажимается**
- Даже при `ALLOW_CLOUD_DELETE=true` — dry-run имеет приоритет

## Уровень 2: SHA-256 верификация

Каждый файл после распаковки:
```python
sha256 = get_file_hash(file_path)
# Сверка с эталоном из ZIP (если доступен)
# Только при совпадении → files_verified=true
```

Блок считается верифицированным только если **все** его файлы имеют совпадающие хеши.

## Уровень 3: Manifest как gate

Удаление разрешено только когда:
```python
entry['files_verified'] == True
and entry['deleted_from_cloud'] == False
and block_age_days > DAYS_TO_KEEP_IN_CLOUD
```

Manifest — единственный источник истины. Браузер не "помнит" состояние.

## Уровень 4: Возрастной порог

```python
days_in_cloud = (datetime.now() - block_date).days
if days_in_cloud < DAYS_TO_KEEP_IN_CLOUD:
    skip_deletion()  # Молодой файл — не трогаем
```

Даже verified-блоки не удаляются, если они "слишком свежие" (по умолчанию 180 дней).

## Уровень 5: Лимит на запуск

```python
deleted_count = 0
for block in candidates:
    if deleted_count >= MAX_DELETE_BLOCKS_PER_RUN:
        break
    delete(block)
    deleted_count += 1
```

`MAX_DELETE_BLOCKS_PER_RUN=1` — за один запуск максимум 1 блок.

## Проверка идемпотентности

- Повторный запуск **не удаляет** уже удаленные блоки (`deleted_from_cloud=true`)
- Не скачивает verified-блоки
- Переобрабатывает partial-блоки (`files_verified=false`)

## Что происходит при сбое

| Сбой | Последствия |
|------|-------------|
| Закрыт браузер до верификации | ZIP остается в TEMP_DIR, manifest не обновлен. Файл не удален. |
| Часть файлов не прошла хеш | `partial=true`, `files_verified=false`. Блок не удаляется. |
| Таймаут скачивания | ZIP не скачан, manifest не тронут. Безопасно. |
| Crash во время удаления | Следующий запуск видит `deleted_from_cloud=true` (если успели пометить) или повторяет (если нет). |

## Dry-run формат лога

```
[DRY-RUN] Удалил бы блок: GROUP: 15 июля 2023 г. (5 файлов)
[DRY-RUN] Дата: 2023-07-15, возраст: 384 дн., verified: True
```

## Восстановление после случайного удаления

Если пользователь вручную удалил файлы с диска, но не из облака:
1. Удалить запись из `backup_manifest.json`
2. Запустить бота — блок скачается заново

Если удалено из облака, но есть локальная копия — потерь нет.
